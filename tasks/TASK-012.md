## (ก) แกนกริดร่วม — `st-garden-service/src/services/grid/core.ts`
- ระนาบ x ขวา / y ลง · นับจากภาพใช้หน่วยพิกเซล · วางแผนปลูกแปลง UTM เป็น (E, −N) หน่วยเมตร
- กติกาเดียวกัน: `frame` (หมุน), `assignToGrid` (แถว/คอลัมน์ = จุดตัดที่ใกล้สุด · **เลข 1 = แถว/คอลัมน์แรกที่มีจุดตัดอยู่ในแปลงจริง** ช่องว่างในแปลงนับรวม · เรียงแถวบน→ล่าง ซ้าย→ขวา), `intersectionsInside` (ไม่รวมบนเส้นขอบ), `awayFrom` (ใกล้กว่า 0.45 ช่อง = จุดเดียวกัน), `gridLines`, `shiftGrid`
- `tree-grid/grid.ts` และ `planting/layout.ts` เรียกแกนนี้แทนโค้ดของตัวเอง · เทสต์แกน `test/grid-core.test.ts` (รวมเทสต์ว่าพิกเซล ×10 ให้แถว/คอลัมน์เท่าเมตร)
- ผลที่เปลี่ยน: เลขแถว/คอลัมน์ของ "นับจากภาพ" นับจากช่องแรกในขอบเขตแปลง (เดิมนับจากต้นแรกที่พบ) — เหมือนวางแผนปลูก

## (ข) เทียบแผนปลูกกับผลนับ — `GET …/planting-plans/{planId}/compare?surveyId=&toleranceM=`
- ผลนับต้องผูกแผนที่ (จุดอ้างอิง) — ไม่ผูก → 422 `SURVEY_NOT_GEOREFERENCED` · แผน/ผลนับต้องเป็นของผู้ใช้และแปลงเดียวกัน
- `planting/compare.ts`: บน UTM · จับคู่หลุม↔ต้นหนึ่งต่อหนึ่ง ใกล้สุดก่อน (greedy) ภายใน `toleranceM` (ค่าเริ่มต้นครึ่งระยะปลูก, ≤ ระยะปลูก) → หลุมมีต้น / หลุมว่าง / ต้นนอกแผน (ในแปลง/นอกแปลง) + ระยะคลาดเฉลี่ย/มากสุด · คำนวณสด ไม่บันทึก
- หน้า `parcels/:parcelId/compare?plan=&survey=` (แท็บ "เทียบแผนกับผลนับ") + ปุ่มจากหน้าแผน ("เทียบกับผลนับ") และหน้าผลนับที่ผูกแผนที่ ("เทียบกับแผนปลูก")

## (ค) ตรวจแล้ว: เดิมบันทึกทันทีที่กด "นับต้นไม้" — ไม่มีขั้นตรวจ/ชื่อ/ปุ่มบันทึก
- ใหม่: "วิเคราะห์ภาพ" (`POST …/tree-surveys/analyze` — ไม่บันทึก) → ขั้นตรวจผลในหน้าเดิม (แผงแก้ไขตัวเดียวกับหน้าผล — `components/tree-survey-editor-panel.component.ts`, พรีวิวร่าง `POST …/tree-surveys/preview`) → ใส่ชื่อ (บังคับ) → "บันทึกผลการนับ" (`POST …/tree-surveys` พร้อม `result` — ไม่ตรวจจับซ้ำ อ่านแค่ขนาดภาพ) · "กลับไปแก้ขอบเขต/มาตราส่วน" ใช้ไฟล์ที่อัปโหลดแล้ว
- ผลนับมีชื่อ (`garden.tree_surveys.name`, migration `0004_tree_survey_name` — nullable) · แก้ชื่อได้ในโหมดแก้ไขของหน้าผล
- `POST …/tree-surveys` แบบไม่มี `result` ยังใช้ได้ (ตรวจจับแล้วบันทึกทันที) เพื่อไม่ทำให้ client เดิมพัง
