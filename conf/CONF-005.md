# CONF-005 — ภาพนับต้นไม้: มาตราส่วน/การผูกกับแผนที่ และประมวลผลที่ไหน

**สถานะ:** ✅ ตัดสินใจแล้ว (ผู้ใช้ 2026-11-23) · **กระทบ:** TASK-010, st-garden-service, st-mfe-garden · **ผู้ตัดสินใจ:** ผู้ใช้

## ปัญหา 1 — มาตราส่วน + ตำแหน่งจริง
สคริปต์ต้นฉบับได้ "ระยะห่างจริง" จากการ**สมมติว่าระยะปลูก = 4 ม.** แล้วคิดมาตราส่วนย้อนกลับ → ค่าเฉลี่ยที่แสดงจึงออกมา ≈ 4 ม. เสมอ ไม่ใช่การวัด · และพิกัดต้นไม้เป็นพิกเซล วางบนแปลงในแผนที่ (SRID 4326) ไม่ได้

| | วิธี | ได้มาตราส่วน | ได้ตำแหน่งบนแผนที่ | หมายเหตุ |
|---|---|---|---|---|
| A | รับ GeoTIFF / orthophoto ที่มีพิกัดในไฟล์ | ✅ | ✅ | แม่นสุด ต้องมีซอฟต์แวร์ทำ ortho (เช่น ของโดรน) · อ่านด้วยไลบรารี GeoTIFF |
| B | ผู้ใช้ปักจุดคู่ภาพ↔แผนที่ ≥ 3 จุด (affine) — เช่นมุมแปลงที่วาดไว้แล้วใน TASK-004 | ✅ | ✅ | ใช้ได้กับภาพทั่วไปที่ถ่ายตั้งฉาก · ผู้ใช้ทำเพิ่ม 1 ขั้น |
| C | คำนวณจาก EXIF ของโดรน (ความสูง, เลนส์, เซนเซอร์) | ✅ ประมาณ | ❌ | ภาพต้องตั้งฉาก · EXIF ไม่ครบในหลายรุ่น |
| D | สมมติระยะปลูก (แบบต้นฉบับ) | ❌ สมมติ | ❌ | ใช้ได้แค่นับจำนวน/แถว |

**ข้อเสนอ:** PoC = **B** (+ D เป็นค่าสำรองโดยติดป้าย "ระยะโดยประมาณจากระยะปลูกที่ระบุ") · ภายหลังเพิ่ม A

## ปัญหา 2 — ประมวลผลที่ไหน
ภาพ 12 ล้านพิกเซลใช้ ≈ 5 วินาทีบน Bun (TASK-010)

| | วิธี | ข้อดี | ข้อเสีย |
|---|---|---|---|
| A | หลังบ้าน แบบ sync + จำกัดขนาดภาพ (เช่นด้านยาว ≤ 4096 px) | ง่าย ตรงกฎ "logic อยู่ใน service" ภาพอยู่ใน bucket แล้ว | request ค้างหลายวินาที · กิน CPU ของ service |
| B | หลังบ้าน แบบ async (สร้างงาน → RabbitMQ → worker → แจ้งผล) | ไม่ค้าง รองรับภาพใหญ่ | ซับซ้อนขึ้น ต้องมีสถานะงาน + event |
| C | ในเบราว์เซอร์ (Web Worker) แล้วส่งผลไปบันทึก | ไม่กิน server | ต้องตรวจผลซ้ำที่หลังบ้าน (ห้ามเชื่อ client) · เครื่องผู้ใช้ช้า |

**ข้อเสนอ:** PoC = **A** · ถ้าภาพจริงใหญ่กว่า/ช้ากว่าที่วัด → B

## ผลการตัดสินใจ
ผู้ใช้ 2026-11-23: **ใช้ตามข้อเสนอ**
1. มาตราส่วน/ตำแหน่ง = **B** ผู้ใช้ปักจุดคู่ภาพ↔แผนที่ ≥ 3 จุด (แนะนำ ≥ 4 เพื่อให้รู้ค่าคลาดเคลื่อน) → affine จากพิกเซลไป UTM (EPSG:32647/32648) แล้วแปลงเป็น `[lng, lat]` · ระยะวัดบน UTM
   - **D** (สมมติระยะปลูก) เป็นค่าสำรองเมื่อไม่ได้ปักจุด — ผลมี `scaleIsEstimate: true` และหน้าจอต้องติดป้าย "ระยะโดยประมาณจากระยะปลูกที่ระบุ" · ไม่มีตำแหน่งบนแผนที่ (MOCK-001)
   - A (GeoTIFF) ทำภายหลัง
2. ประมวลผล = **A** หลังบ้านแบบ sync · ด้านยาวของภาพ ≤ **4096 px** (`MAX_IMAGE_SIDE_PX`) — หน้าบ้านย่อภาพก่อนอัปโหลด · ถ้าภาพจริงช้ากว่าที่วัด → เปิด CONF ใหม่เพื่อย้ายไป B (async)

ข้อจำกัดที่ต้องบอกผู้ใช้: affine ใช้ได้กับภาพถ่ายตั้งฉาก (nadir) · ภาพถ่ายเฉียง/พื้นที่ลาดชันมากจะคลาด → ดูค่า `georef.rmsErrorM` ในผลลัพธ์
